# Дизайн и план сборки Claude-кабинета работодателя

## Цель

Собрать в приложении Claude законченный рабочий кабинет работодателя, который:

- принимает обычные сообщения, транскрибации и файлы;
- сам предлагает понятное меню действий;
- использует знания конкретного бизнеса и голос работодателя;
- выполняет повторяемые задачи через отдельные скиллы;
- задаёт вопросы только тогда, когда без факта или решения нельзя продолжить;
- выдаёт готовый результат, следующий шаг и предложение обновить базу;
- не требует участия настройщика после передачи.

Под «ноль вопросов» понимаются ноль технических вопросов и вопросов о навигации. Claude обязан уточнять недостающие факты и просить подтверждение важных бизнес-решений, чтобы не додумывать их.

## Архитектура

Система состоит из четырёх слоёв:

1. **Аккаунт работодателя.** Все доступы и данные принадлежат работодателю.
2. **Claude Project.** Хранит знания, инструкции и историю работы одного бизнеса.
3. **Семь скиллов.** Каждый отвечает за отдельный тип работы.
4. **Стартовый интерфейс.** Файл `00_НАЧАТЬ_ЗДЕСЬ.md` и команда `СТАРТ`, которые открывают меню действий.

## Семь скиллов

### 1. Навигатор рабочего кабинета — создать

Назначение: принимать неструктурированные запросы, показывать меню, определять задачу и направлять её в нужный скилл.

Навигатор не должен самостоятельно выполнять глубокую стратегическую или редакторскую работу. Его задача — выбрать маршрут, проверить входные данные и назвать следующий шаг.

Меню:

```text
Что делаем сегодня?

1 — Написать пост в Telegram
2 — Сделать сценарий Reels
3 — Собрать сторисы
4 — Разобрать созвон с клиентом
5 — Разобрать кастдев
6 — Собрать лид-магнит или воронку
7 — Подготовить прогрев
8 — Разобрать диалог с человеком
9 — Проверить упаковку профиля
10 — Посмотреть состояние бизнеса
11 — Разобрать новый файл
0 — Своя задача
```

### 2. Producer Megamozg — использовать существующий

Закрывает стратегию, продукты, аудиторию, кастдевы, лид-магниты, воронки, прогревы, запуски, продажи, команду и еженедельный обзор бизнеса.

Нужно добавить в стартовую документацию готовые команды для четырёх режимов:

- `РАЗБОР ЦА`;
- `СОБРАТЬ ВОРОНКУ`;
- `РАЗОБРАТЬ ПРОДАЖИ`;
- `ОБЗОР БИЗНЕСА`.

### 3. Разбор клиента — создать

Вход: транскрибация созвона, заметки, материалы клиента и задача разбора.

Выход:

1. Краткая выжимка разговора.
2. Факты, наблюдения и гипотезы по отдельности.
3. Главная проблема клиента.
4. Решения, принятые на созвоне.
5. План клиента на 7 и 30 дней.
6. Задачи с владельцем и сроком, если они были названы.
7. Риски и недостающие данные.
8. Клиентская версия разбора без внутренних комментариев.
9. Список информации, которую нужно обновить в базе проекта.

Скилл не выдумывает диагнозы, обещания, сроки и цифры. Если их нет в разговоре, помечает пробел.

### 4. Content-завод — использовать существующий

Закрывает производство контента из транскрибации или статьи: статья, короткие посты, Reels, Telegram-посты, карусели и контент-план.

Для ежедневной работы добавить облегчённые команды:

- `ОДИН ПОСТ`;
- `ОДИН REELS`;
- `СЕРИЯ СТОРИС`;
- `ПОЛНЫЙ КОНТЕНТ-ЗАВОД`.

Полный пакет запускается только по прямой просьбе, чтобы Claude не создавал 24 единицы вместо одного нужного поста.

### 5. Упаковка профиля — создать

Вход: ссылка или скриншоты профиля, описание продукта, аудитория и цель профиля.

Выход:

1. Что человек понимает о профиле за первые секунды.
2. Аудит имени, шапки, ссылки и призыва к действию.
3. Аудит закреплённых публикаций.
4. Аудит актуальных сторис и навигации.
5. Какие доказательства экспертности видны, а какие потеряны.
6. Предлагаемая структура профиля.
7. Конкретные варианты текста с пометкой, какие факты нужно подтвердить.
8. План изменений по приоритету: сегодня, на неделе, позже.

### 6. Storytelling-corrector — использовать существующий

Запускается для усиления готового черновика. Сначала диагностирует, затем переписывает только после согласия человека.

### 7. Antidetector — использовать существующий

Используется как финальная редактура русского текста. Не должен менять факты, цифры и смысл.

## База знаний Claude Project

В обычном Claude Project знания лучше хранить отдельными файлами с цифровыми префиксами. Это заменяет визуальные папки и упрощает поиск.

### Обязательные файлы

| Файл | Содержание |
| --- | --- |
| `00_НАЧАТЬ_ЗДЕСЬ.md` | меню, три примера работы, команда `СТАРТ`, что делать при ошибке |
| `01_ПАСПОРТ_РАБОТОДАТЕЛЯ.md` | роль, опыт, сильные стороны, ограничения, цели |
| `02_ПАСПОРТ_БИЗНЕСА.md` | модель бизнеса, команда, каналы, текущие приоритеты |
| `03_ПРОДУКТЫ_И_ОФФЕРЫ.md` | продукты, цены, результаты, состав, доказательства |
| `04_АУДИТОРИЯ.md` | сегменты, кастдевы, язык, боли, возражения |
| `05_ГОЛОС_И_СТИЛЬ.md` | тон, лексика, примеры, запреты, обращение к аудитории |
| `06_КОНТЕНТНАЯ_СИСТЕМА.md` | рубрики, площадки, форматы, CTA, частота |
| `07_ВОРОНКИ_И_ПРОГРЕВЫ.md` | действующие связки, лид-магниты, этапы прогрева |
| `08_ПРОДАЖИ_И_ДИАЛОГИ.md` | скрипты, возражения, удачные и неудачные диалоги |
| `09_РАЗБОРЫ_КЛИЕНТОВ.md` | структура разборов и обезличенные эталоны |
| `10_МЕТРИКИ_И_РЕШЕНИЯ.md` | цифры, гипотезы, решения и результаты |
| `11_ПРАВИЛА_РАБОТЫ.md` | что Claude может делать сам, что требует подтверждения |
| `99_ВХОДЯЩИЕ.md` | правила обработки новых файлов и транскрибаций |

Сырые транскрибации хранятся отдельно и получают понятные имена: дата, тип разговора, участник и тема. В основные файлы попадает обработанная выжимка, а не копия всей транскрибации.

## Инструкции проекта

Проектные инструкции должны закреплять следующие правила:

1. Сначала определить задачу и найти нужные файлы проекта.
2. Если запрос расплывчатый, показать меню навигатора.
3. Не задавать вопросы, ответы на которые уже есть в базе.
4. Если данных нет, задать один короткий вопрос за раз.
5. Отделять факты от гипотез и рекомендаций.
6. Не придумывать результаты, отзывы, цифры, биографию и позицию работодателя.
7. Писать в голосе работодателя, опираясь на файл `05_ГОЛОС_И_СТИЛЬ.md`.
8. После значимой задачи выдавать: результат, что проверить, следующий шаг.
9. Предлагать обновить базу, если появились новые подтверждённые данные.
10. Для важных публичных текстов предлагать финальную проверку через Antidetector.

## Пошаговый план сборки

### Этап 0. Зафиксировать границы — 30 минут

- Убедиться, что аккаунт Claude принадлежит работодателю.
- Проверить тариф, доступ к Projects, Skills и выполнению кода.
- Не хранить пароли работодателя в документации или базе проекта.
- Решить, какие данные запрещено загружать: персональные данные клиентов, платёжные данные, медицинские сведения и другие чувствительные материалы.
- Зафиксировать дату передачи и количество времени на тестирование.

**Готово, когда:** понятны владелец аккаунта, разрешённые данные и дата передачи.

### Этап 1. Собрать все исходники — 2–4 часа

Собрать в одну временную папку:

- описание работодателя и бизнеса;
- продукты, цены, программы и офферы;
- кастдевы и интервью;
- 10–20 характерных постов;
- 5–10 транскрибаций Reels, эфиров или сторис;
- примеры прогревов;
- действующие лид-магниты и воронки;
- удачные и неудачные диалоги с людьми;
- примеры клиентских разборов;
- отзывы, кейсы и доказательства;
- скриншоты и ссылки профилей;
- актуальные метрики и решения.

Составить реестр: имя файла, тип, дата, владелец, можно ли использовать в Claude, куда он пойдёт.

**Готово, когда:** у каждого материала понятны назначение и статус доступа.

### Этап 2. Собрать голос работодателя — 1–2 часа

На основе его текстов и транскрибаций создать `05_ГОЛОС_И_СТИЛЬ.md`:

- обращение на «ты» или «вы»;
- длина и ритм фраз;
- допустимый сленг;
- любимые выражения;
- слова и формулировки, которые он не использует;
- отношение к мату и жёсткой лексике;
- структура постов, Reels и сторис;
- 5–10 примеров «это звучит как он»;
- 5 примеров «так писать нельзя».

**Готово, когда:** работодатель узнаёт себя в двух тестовых абзацах.

### Этап 3. Превратить сырьё в базу — 3–6 часов

- Заполнить 12 обязательных файлов проекта.
- Сократить дубли и противоречия.
- Все сомнительные сведения пометить как гипотезы.
- Даты и цифры снабдить контекстом.
- Для кастдевов выделить прямые формулировки аудитории.
- Для клиентских разборов сделать обезличенные эталоны.
- Создать индекс сырых материалов и ссылки на источники.

**Готово, когда:** на любой базовый вопрос о бизнесе находится один актуальный ответ, а не три противоречивых.

### Этап 4. Доработать скиллы — 4–7 часов

1. Собрать `navigator`.
2. Собрать `client-review`.
3. Собрать `profile-packaging`.
4. Добавить облегчённые режимы в Content-завод либо закрепить их в навигаторе.
5. Проверить описания скиллов: по ним Claude понимает, когда какой навык включать.
6. Упаковать каждый скилл отдельным ZIP, где `SKILL.md` находится в корне пакета.
7. Сохранить исходники и версии в резервной папке или репозитории.

**Готово, когда:** каждый скилл решает одну понятную задачу и не дублирует соседний.

### Этап 5. Создать Claude Project — 1–2 часа

В аккаунте работодателя:

1. Включить выполнение кода и Skills в настройках.
2. Загрузить и включить семь скиллов через `Customize → Skills`.
3. Создать проект `Рабочий кабинет работодателя` и при желании добавить его имя в название.
4. Вставить проектные инструкции.
5. Загрузить 12 файлов базы знаний.
6. Добавить исходные материалы, которые действительно нужны для поиска.
7. Создать первый чат и написать `СТАРТ`.
8. Убедиться, что Claude показывает меню без дополнительных объяснений.

**Готово, когда:** новый чат внутри проекта начинает работу по команде `СТАРТ`.

### Этап 6. Провести тестирование — 2–4 часа

Проверить минимум 15 сценариев:

1. Пост Telegram из транскрибации.
2. Один сценарий Reels.
3. Серия сторис.
4. Полный контент-пакет.
5. Разбор созвона с клиентом.
6. Клиентская версия разбора.
7. Выжимка кастдева.
8. Лид-магнит.
9. Простая воронка.
10. Прогрев.
11. Ответ человеку в диалоге.
12. Аудит упаковки профиля.
13. Еженедельный обзор бизнеса.
14. Работа при нехватке данных.
15. Проверка, что Claude не придумал факты.

Для каждого теста поставить оценку по пяти критериям:

- выбрал правильный скилл;
- нашёл нужные материалы;
- не выдумал факты;
- попал в голос;
- выдал применимый результат и следующий шаг.

Если сценарий не проходит дважды, исправить инструкции или скилл, а не объяснять работодателю обходной путь.

**Готово, когда:** все критические сценарии проходят без помощи настройщика.

### Этап 7. Сделать передачу — 1–2 часа

Подготовить:

- одностраничную памятку `С чего начать`;
- визуальный гайд по структуре кабинета;
- короткое видео экрана: вход, команда `СТАРТ`, три задачи;
- список команд для копирования;
- резервную копию базы и всех ZIP-скиллов;
- журнал версий;
- правило восстановления: переустановить скилл, загрузить базу, вставить инструкции.

Провести один совместный тест:

1. Работодатель открывает новый чат сам.
2. Пишет `СТАРТ`.
3. Выбирает три реальные задачи.
4. Проверяет результат.
5. Сам добавляет один новый материал.

**Готово, когда:** работодатель выполняет три задачи без подсказок настройщика.

## Критический маршрут перед отъездом

Если материалы уже доступны, рабочую версию можно собрать примерно за 14–25 часов чистой работы:

### День 1

- собрать и проиндексировать материалы;
- заполнить паспорт бизнеса, продукты, аудиторию и голос;
- подготовить остальные файлы базы.

### День 2

- собрать три недостающих скилла;
- установить семь скиллов;
- создать Claude Project и загрузить базу.

### День 3

- провести 15 тестов;
- исправить критические сбои;
- записать видео и провести передачу.

Если времени меньше, не сокращать паспорт бизнеса, голос, навигатор, разбор клиента и тестирование. На второй этап можно перенести плагины, внешние коннекторы, автоматическую публикацию и сложные интеграции.

## Стоп-факторы

- Работодатель не имеет собственного аккаунта или доступа к настройкам Skills.
- Материалы разбросаны и неизвестно, какие из них актуальны.
- Нет примеров голоса работодателя.
- В Claude загружаются чувствительные данные без разрешения.
- Один скилл пытается делать все задачи.
- Система передаётся без тестирования работодателем.

## Критерии завершения

Работа завершена, когда:

1. Работодатель владеет аккаунтом и доступами.
2. Проект открывается командой `СТАРТ` и показывает меню.
3. Семь скиллов установлены, включены и имеют резервные копии.
4. База знаний содержит 12 актуальных файлов.
5. Пятнадцать тестовых сценариев пройдены.
6. Работодатель сам выполнил три реальные задачи.
7. Переданы памятка, видео, резервная копия и инструкция восстановления.
