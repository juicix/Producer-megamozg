# Диагностика и настройка кабинета

Проверить, способен ли Claude выполнять реальные задачи по данным бизнеса, а не по догадкам.

## Проверка базы

Проверить наличие и содержательность:

1. `01_ПАСПОРТ_РАБОТОДАТЕЛЯ.md` — роль, ограничения, формат помощи.
2. `02_ПАСПОРТ_БИЗНЕСА.md` — цель, активы, команда, узкое место.
3. `03_ПРОДУКТЫ_И_ОФФЕРЫ.md` — актуальные продукты, результат, цена, условия.
4. `04_АУДИТОРИЯ.md` — подтверждённые сегменты и живой язык.
5. `05_ГОЛОС_И_СТИЛЬ.md` — правила голоса и минимум три примера.
6. `06_КОНТЕНТНАЯ_СИСТЕМА.md` — каналы, задачи и производство.
7. `07_ВОРОНКИ_И_ПРОГРЕВЫ.md` — только действующие механики.
8. `08_ПРОДАЖИ_И_ДИАЛОГИ.md` — правила, следующий шаг, ограничения.
9. `10_МЕТРИКИ_И_РЕШЕНИЯ.md` — период, фактические показатели, решения.
10. `11_ПРАВИЛА_РАБОТЫ.md` и `12_ОБУЧЕНИЕ_СИСТЕМЫ.md` — границы и накопленные правки.

Не считать файл заполненным, если в нём остались только заголовки, подсказки или плейсхолдеры.

## Статус готовности

Выдать один статус:

- **ГОТОВО** — заполнены первые пять файлов, нет критических противоречий, можно выполнить три контрольные задачи.
- **МОЖНО РАБОТАТЬ С ОГРАНИЧЕНИЯМИ** — базовые данные есть, но отдельные результаты требуют проверки.
- **НЕ ГОТОВО** — отсутствуют продукт, аудитория, голос или границы обещаний.

Показать не процент, а конкретные последствия: какие задачи уже можно выполнять и где Claude будет вынужден спрашивать.

## Поиск конфликтов

Сопоставить повторяющиеся сведения между файлами:

- цены, сроки, форматы и состав продуктов;
- цель бизнеса и текущие приоритеты;
- сегменты аудитории;
- CTA и следующий шаг воронки;
- допустимые обещания, скидки и рассрочки;
- роли и владельцы задач.

Не выбирать версию самостоятельно. Показать обе формулировки, источник и задать один вопрос о действующей версии.

## Диалог настройки

1. Сначала показать статус и не более пяти критических пробелов.
2. Выбрать пробел, который блокирует больше всего задач.
3. Задать один короткий вопрос.
4. После ответа подготовить готовый фрагмент для конкретного файла.
5. Спросить подтверждение обновления, если среда не может изменить файл сама.
6. Перейти к следующему критическому пробелу.

Не задавать вопросы о данных, которые уже есть в Project. Не пытаться заполнить всю базу за один ответ.

## Итог настройки

После устранения критических пробелов выполнить или предложить три проверки:

1. Один Telegram-пост по реальному материалу.
2. Один разбор реального клиентского созвона.
3. Обзор бизнеса с тремя приоритетами без придуманных метрик.

Финальный ответ:

```text
Статус: ГОТОВО / МОЖНО РАБОТАТЬ С ОГРАНИЧЕНИЯМИ / НЕ ГОТОВО

Уже работает:
- ...

Требует проверки:
- ...

Следующий шаг:
- ...
```
